# v1.2.0 Portfolio Readiness

Readiness decision for this audit branch:

```text
B. READY_WITH_DOCUMENTED_LIMITATION
```

This document records the release-readiness decision that authorized the
v1.2.0 release. The release commit performs the version bump, but still does not
perform live provider calls or Stage 4 reruns.

## What is ready

- Public architecture documents have been aligned to current source/runtime
  boundaries.
- README links now point to v2 portfolio materials and current runtime docs.
- Agent final-report synthesis is documented as a current post-loop presentation
  feature.
- Workflow and Agent remain distinct UI/runtime modes.
- Stage 4 benchmark artifacts remain frozen and are not reinterpreted.
- CI/runtime maintenance changes are inventoried.

## R1-R4 reliability patch status

`dec7bc71651884154a256797b2dd330cf3946f14` is not an ancestor of current
`main`:

```text
provider_reliability_R1_R4_merged = false
```

The v1.2.0 candidate must not claim those patches as merged behavior.

## Documented limitation

The official Stage 4 benchmark corresponds to the frozen v1.1.0 Agent runtime
before Agent final-report synthesis was added. Current runtime documentation may
describe the final-report layer, but public benchmark claims must continue to
use the frozen Stage 4 evidence boundary.

The existing Deep Research Workflow has a documented historical reliability
limitation around provider schema/report-quality/strict synthesis validation.
That limitation blocks production-reliability claims, but it is not treated as a
blocker for a truthful portfolio release when clearly disclosed.

## Agent final-report evidence

The Agent final-report layer is accepted as feature evidence from prior
mainline smoke/replay work and source-level validation. This readiness audit did
not run a fresh live smoke:

```text
fresh_main_smoke_attempted = false
provider_requests = 0
```

If a release owner wants fresh deployed-runtime confirmation, run at most one
Agent exact-sample smoke in a separate authorized task before tagging.

## Forbidden claims

- Strong semantic grounding has been proven.
- Large-scale strict blind generalization has been proven.
- Agent semantic research quality improved by 93.3 percentage points.
- Commercial production readiness is established.
- Long-term stability or hallucination elimination is proven.

## Release prerequisites still required

Before an actual v1.2.0 release:

1. Run final local release tests on the release commit.
2. Verify GitHub CI on the pushed release branch or `main`.
3. Bump package/runtime to `1.2.0+portfolio`.
4. Create annotated tag `v1.2.0-portfolio` only after gates pass.
5. Create a GitHub Release only if separately authorized.
